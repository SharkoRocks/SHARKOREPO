Reflection: GitHub vs. WordPress Development

Developing a site through GitHub Pages is a manual, technical process that requires a deep understanding of syntax and file structure. In contrast, WordPress offers a managed environment where the interface handles the heavy lifting. The most significant difference is the level of control: GitHub requires you to build every piece from scratch, while WordPress provides a pre-built framework that you simply customize.

For a new learner, the most significant challenge in GitHub is "well-formedness"—one missing bracket or a lowercase file extension can break the entire site. In WordPress, the challenge is navigating the massive amount of settings and plugins, which can be overwhelming. The advantage of GitHub is total creative freedom and no cost, whereas WordPress provides speed and ease of use through its visual editors.

Modifying the layout in GitHub requires editing CSS and understanding the grid or flexbox systems, which is time-consuming. In WordPress, organization is usually handled through a "drag-and-drop" interface, though it can be frustrating when a theme doesn't allow a specific change you want. GitHub development requires knowledge of HTML, CSS, and terminal commands, while WordPress primarily requires digital literacy and an eye for design.

To improve these sites, I would want to learn more about automated styling and better asset management. Moving forward, having a grasp of both the "under the hood" coding and the user-friendly CMS side provides a well-rounded view of how the web functions.
